Same particles, four engines

GPU Playground

Each demo runs the exact same simulation: up to 16 million particles pulled towards your mouse. Only one thing changes: where the work happens (and, for 2a and 2b, which language the WebAssembly was written in). Watch the frame rate and the bar at the bottom of each demo.

Demo 1

Plain JavaScript

A JS loop moves each particle on the CPU, one after another, then copies the positions to the GPU to draw.

  • Move particles (JS loop)CPU
  • Copy positionsCPU → GPU
  • Draw pointsGPU
 Demo 2a

WebAssembly: AssemblyScript

The same loop in AssemblyScript (TypeScript-like), compiled to WebAssembly, 4 particles per instruction. Much faster, but still one CPU core.

  • Move particles (WASM + SIMD)CPU
  • Copy positionsCPU → GPU
  • Draw pointsGPU
 Demo 2b

WebAssembly: Rust

The same loop in Rust, compiled to WebAssembly with the same SIMD trick. Compare it with 2a: same idea, different language.

  • Move particles (WASM + SIMD)CPU
  • Copy positionsCPU → GPU
  • Draw pointsGPU
 Demo 3

WebGPU compute

The particles live on the GPU. JS sends two commands; thousands of GPU threads move every particle at once.

  • Send 2 commandsCPU
  • Move particles (compute shader)GPU
  • Draw from the same bufferGPU

Try this

  1. Open each demo at 1M, Light. All four should hold your screen's full frame rate.
  2. Switch to 4M. JavaScript drops frames (its CPU bar goes red); WebAssembly and WebGPU don't. The language alone made the CPU work about 7× faster.
  3. Switch to Heavy (16× the maths per particle). JavaScript crawls, WebAssembly drops frames, WebGPU stays smooth: it runs the maths on thousands of GPU threads at once.
  4. Try 16M, Heavy. Only WebGPU stays usable.
  5. Compare 2a and 2b in Heavy mode: Rust's "Move particles" time is lower than AssemblyScript's, though both run the same SIMD maths.
  6. Come back here: the chart below compares the frame rates you got.

Your results

Frames per second each demo reached in this browser. Higher is better; your screen's refresh rate is the ceiling. Above 1M, every demo still simulates every particle but draws only 1M of them, so drawing doesn't become the bottleneck.
